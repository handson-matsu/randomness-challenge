# RANDOM? — 人間はランダムに選べるのか

A/Bを100回選んで、公平・独立なランダム列と4項目で比較する日本語Webアプリです。総合点やランダム／非ランダムの断定はしません。

## 起動

追加ライブラリやビルドは不要です。Python 3で次を実行します。

```sh
cd site
python3 -m http.server 5173 --bind 127.0.0.1 --directory dist
```

ブラウザで http://localhost:5173 を開きます。`file://` では比較データの取得ができないため、HTTPサーバーを使ってください。公開時はHTTPSを使用します。

## GitHub Pages

GitHub Pagesでブランチのルート（`/ (root)`）を公開すると、リポジトリ直下の `index.html` からアプリを表示します。`.nojekyll` により静的ファイルをそのまま配信します。

アプリの編集元は `site/dist/` です。更新時は次のコマンドで公開用の5ファイルをルートに同期し、両方をコミット・プッシュしてください。

```sh
cp site/dist/index.html site/dist/style.css site/dist/app.mjs site/dist/stats.mjs site/dist/distribution.json .
```

固定分布データはコピーするだけで、公開時やユーザーのアクセス時には再生成しません。

## 内容

- タップ・クリック・A/Bキーによる100回入力、進捗、選択履歴、リセット
- A/Bバランス、切り替え、最長連続、重複を含むABA/BABの4項目
- 100万組の固定シミュレーション分布、観測位置、観測値を含む片側割合
- 50:50ちょうどの割合、参考の連の分布
- `crypto.getRandomValues()` によるコンピュータ試行と横並び比較。結果による引き直しはしません
- モバイル対応、キーボード操作、動きを減らす設定への対応

## 統計の仕様

`site/scripts/simulate.mjs` はNode.jsの `crypto.randomBytes()` で100万組×100回を生成します。各バイトの下位ビットを使うのでA/Bは各1/2です。生成済みデータと生成条件は `site/dist/distribution.json` に保存しています。

割合は基準分布の平均以下なら下側（観測値以下）、平均より上なら上側（観測値以上）の経験的割合です。バランスはAの回数で比較し、50:50を高得点にしません。未観測の範囲は「100万組中0組（0%とは限りません）」と表示します。これはランダムである確率でも、複数検定を調整した検定結果でもありません。

回答データはブラウザに保存・外部送信しません。ページ読み込み時に1回、アクセス記録用のGoogle Apps Scriptへアプリ名のみをGET送信します。アプリ内操作では再送せず、通信失敗時も操作に影響しません。再読み込みすると入力は消えます。

## 検証

Node.js 20以上で：

```sh
cd site
node --test tests/stats.test.mjs
node scripts/simulate.mjs # 基準データを作り直す場合のみ
```

ブラウザの回帰検証には別途PlaywrightとChromiumが必要です。サーバー起動中に `node tests/browser.mjs` を実行します。必要なら `PLAYWRIGHT_MODULE` でモジュールの場所、`CHROME_PATH` でChrome実行ファイルを指定できます。

統計テストは極端な列、重複、10文字の全1024列、裾の包含、基準分布の総数と理論平均を確認します。ブラウザテストは100回入力、リセット、反復比較、375pxの横はみ出し、実行時エラー、補助WebMCP APIの読み取りを確認します。
